## Overview

PROMPT-Backend will be a specialized version of the PROMPT Protocol optimized for backend development, APIs, microservices, and server-side applications.

## Target Domain

- Backend APIs (REST, GraphQL, gRPC)
- Microservices architecture
- Server-side applications
- Database-heavy applications
- Background jobs and workers

## Potential Tech Stack

- **Languages:** Python, Go, Java, Node.js, Rust
- **Frameworks:** FastAPI, Express, Spring Boot, Django, Gin
- **Databases:** PostgreSQL, MongoDB, Redis, Elasticsearch
- **Message Queues:** RabbitMQ, Kafka, Redis Pub/Sub
- **Tools:** Docker, Kubernetes, API Gateway

## Proposed P.R.O.M.P.T Categories

This is a draft proposal. Categories may differ from Web version:

### P - Performance & Scalability
- Database query optimization
- Caching strategies (Redis, memcached)
- Connection pooling
- Async/concurrent processing

### R - Reliability & Resilience
- Error handling and recovery
- Retry mechanisms
- Circuit breakers
- Health checks and monitoring

### O - Observability
- Logging (structured logs)
- Metrics (Prometheus, StatsD)
- Tracing (OpenTelemetry)
- Alerting

### M - Modeling & Data
- Database schema design
- Data validation
- Migration strategies
- Indexing

### P - Patterns & Architecture
- Design patterns (Repository, Service, etc.)
- Dependency injection
- Middleware patterns
- API versioning

### T - Testing & Security
- Unit, integration, E2E tests
- Authentication/Authorization
- Input validation
- Security best practices
